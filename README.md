
# Документация по Git версии и командной политике

## Git версионирование

- Ветки по темам: `feature/01-basics`, `feature/02-cypher-crud` и т.д.
- Conventional Commits: `docs:`, `fix:`, `upd:`, `init:`, `style:`, `feat:`, `ref:`
- Проверка: все запросы тестируются в Neo4j Browser перед мержем в `main`.
- Обновление: по мере изучения новых тем.

---

### Формат коммитов

`<тип>: <описание>`

### Типы:

| Тип  | Назначение                                              | Примеры                                                      |
|-------|---------------------------------------------------------|--------------------------------------------------------------|
| **feat**  | создание нового файла или функции                    | `feat: добавлен модуль авторизации`                          |
| **style** | форматирование файла (пробелы, табуляции, оформление) | `style: исправлено выравнивание кода`                        |
| **init**  | первоначальное создание репозитория или проекта   | `init: создан репозиторий справочника Neo4j`                |
| **docs**  | добавление или изменение разделов документации     | `docs: добавлен раздел CRUD операций`                        |
| **fix**   | исправление ошибок в коде или документации         | `fix: исправлен пример DETACH DELETE`                        |
| **upd**   | обновление устаревшей информации                   | `upd: обновлён синтаксис под Neo4j 5.x`                      |
| **ref**   | реструктуризация без изменения функционала        | `ref: переименованы файлы согласно конвенции`               |

---

### Примеры:

- ✅ `init: создан репозиторий справочника Neo4j`
- ✅ `docs: добавлен раздел CRUD операций`
- ✅ `fix: исправлен пример DETACH DELETE`
- ✅ `upd: обновлён синтаксис под Neo4j 5.x`
- ✅ `ref: переименованы файлы согласно конвенции`

---

### Замечания:
> ❌ "изменения"  
> ❌ "правки"  
> ❌ "обновил файл"
